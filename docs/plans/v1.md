# jiaoag v1 实施计划

单用户编码 agent：`jiaoag-server` 持有会话/任务/工具执行，`jiaoag-tui` 只做渲染与审批，两者通过 WebSocket 长连接通信。v1 的完成定义是：**在指定仓库里说「给 X 函数加测试」→ 读文件 → 流式输出 → 出 diff → 批准落盘 → 跑 `go test` → 回显结果**。

决策依据见 `CONTEXT.md` 与 `docs/adr/0001..0003`。

---

## 1. 目录与依赖方向

```
jiaoag/                          module github.com/kennethfan/jiaoag
├── cmd/
│   ├── jiaoag-server/main.go
│   └── jiaoag-tui/main.go
├── internal/
│   ├── protocol/     # 线上契约：消息、事件、错误码（不 import 其他 internal 包）
│   ├── config/       # ~/.config/jiaoag/config.yaml，key 解析（$ENV / file:）
│   ├── store/        # SQLite：会话、任务、事件、工具调用、审批、提案、审计
│   ├── perm/         # 权限策略：路径边界、工具分级、命令白名单、hash CAS
│   ├── llm/          # Provider 接口 + openai 兼容 + anthropic 适配器
│   ├── tools/        # read/grep/glob/write/edit/run_command/git
│   ├── agent/        # 任务状态机 + 多步循环 + 事件发射（依赖 Emitter 接口）
│   ├── server/       # WS hub、会话注册表、任务调度、事件回放
│   └── tui/          # bubbletea：会话列表 / 对话 / 审批弹层
└── docs/{adr,plans,agents}
```

依赖只允许单向：`cmd → server|tui → agent|store|perm|tools|llm → protocol`。`agent` 不得 import `server` 或 `tui`；`protocol` 不得 import 任何内部业务包。

## 2. 领域状态机

**任务 Task**：`queued → running ⇄ waiting_approval → completed | failed | canceled`

- `waiting_approval` 由工具调用阻塞触发，审批结果沿事件流回传后回到 `running`。
- 取消：`ctx` 取消贯穿 provider 调用与命令执行；已落盘的文件不回滚（回滚靠 git）。
- 任务生命期与连接解耦：连接断开不改变任务状态。

**工具调用 ToolCall**：`requested → (auto_allowed | approved | denied) → running → ok | error | timeout`

## 3. 线上协议（WS，JSON）

信封：`{v: 1, id, type, payload}`；服务端事件额外带 `{session_id, seq}`，`seq` 为会话内单调递增 int64。

**C→S**：`session.create{workspace, provider, model}`、`session.list`、`task.submit{session_id, text}`、`task.cancel{task_id}`、`event.subscribe{session_id, from_seq}`、`approval.respond{approval_id, decision: allow_once|allow_session|deny, note}`

**S→C**：`hello{server_version, protocol_version}`、`session.updated`、`event{...}`、`error{code, message}`

**事件类型（v1）**：`task.queued|started|finished`、`round.started`、`assistant.delta|message`、`tool.requested`、`approval.requested{approval_id, risk, diff_ref}`、`approval.resolved{decision, source}`、`proposal.created{path, diff, base_hash}`、`proposal.applied{new_hash}`、`tool.result{status, output_preview, truncated, duration_ms}`、`error{code, retryable}`

**回放语义**：客户端记录每个会话已见的最大 `seq`；重连时 `event.subscribe{from_seq: last+1}`，服务端从库里补发。客户端所有状态必须可从事件流重建。

## 4. 数据表（SQLite，WAL，`busy_timeout=5000`）

| 表 | 关键列 |
|---|---|
| `sessions` | id TEXT PK, workspace, provider, model, title, created_at, updated_at |
| `tasks` | id PK, session_id, status, prompt, created_at, started_at, finished_at, error, prompt_tokens, completion_tokens |
| `events` | session_id, seq, type, payload JSON, created_at，PK(session_id, seq) |
| `tool_calls` | id PK, task_id, name, args JSON, status, approval_id, output_preview, output_path, duration_ms, created_at |
| `approvals` | id PK, tool_call_id, kind, risk, decision, source(user/policy), requested_at, resolved_at, note |
| `proposals` | id PK, task_id, path, diff, base_hash, new_hash, status, applied_at |
| `audit` | id PK, ts, actor, action, tool_call_id, detail JSON（只追加，不更新） |

写入串行化：单写者（一个 goroutine 或 `BEGIN IMMEDIATE`），其余读走 WAL 快照。事件追加与 `tool_calls` 状态变更在同一事务内，避免「事件有、记录无」。

## 5. 权限策略（`internal/perm`）

第 3 层的取舍见 `docs/adr/0004-default-deny-command-whitelist.md`。

按顺序判定，短路返回：

1. **路径边界**：`filepath.EvalSymlinks` 后必须落在 workspace 根之内，否则 `deny(path_outside_workspace)`。
2. **工具分级**：只读工具（read/grep/glob、`git status|diff|log`）→ 自动放行；写入工具 → 必审批（生成变更提案）；`run_command` → 见 3。
3. **命令白名单（默认拒绝）**：仅当命令 argv **不含任何 shell 元字符**（`| & ; < > $ \` ( ) * ? [ ] ~`）且首 token 命中白名单（`go build|test|vet|run`、`git status|diff|log|show|branch`、`ls`、`cat`、`head`、`wc`）时自动放行；其余一律需审批。**不做「危险命令黑名单」**——字符串检测无法防住命令替换与编码执行。
4. **执行约束**：`cwd` 强制为 workspace 根；`env` 剥离密钥类变量（`*KEY*`、`*TOKEN*`、`*SECRET*`）；单命令超时默认 120s；输出截断 32KB（全文落 `~/.local/share/jiaoag/outputs/`）。
5. **落盘 CAS**：`write/edit` 批准时记录目标文件 sha256；落盘前重算，不等则拒绝并要求重新出 diff（`stale_proposal`）。
6. **审批来源**：`policy`（自动放行）或 `user`（`allow_once` / `allow_session`，后者仅对同一 tool+args hash 生效）。全部写入 `audit`。

## 6. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M0 骨架** | go.mod、目录、config 加载、server 起 HTTP `/healthz`、TUI 连接并握手 `hello` | 两个进程互通，配置缺失时报错清晰 |
| **M1 事件与存储** | 7 张表 + 迁移、事件追加（seq）、回放查询 | 手写事件落库，断开重连能按 seq 补发 |
| **M2 供应商** | `Provider` 接口 + openai 兼容（流式 + tool_calls）+ anthropic（content block / tool_result） | `httptest` 模拟 SSE，两家都能出流式文本与工具调用 |
| **M3 只读闭环** | agent 循环（轮数上限、ctx 取消）+ read/grep/glob + TUI 流式渲染 | 问「这仓库结构是什么」能读到真实文件并作答 |
| **M4 写入与审批** | 变更提案、diff 渲染与翻页、审批协议、hash CAS、write/edit | 出 diff → 批准 → 落盘 → 拒绝时磁盘无变化 |
| **M5 执行与审计** | `run_command` + 权限策略 + 超时/env 剥离/输出落文件 + git 只读工具 + 审计表 | 跑 `go test ./...` 并把结果回显 |
| **M6 并发与容错** | 多会话并行、同仓警告、断连继续跑、事件回放、取消 | 两会话同时跑；杀掉 TUI 再重连，事件不丢 |

合计约 9 人日（AI 辅助下压缩到 4–6 天），M6 完成即达 v1 验收。

## 7. 依赖与开放问题

- 引入 `github.com/pmezard/go-difflib`（unified diff）与 `github.com/gorilla/websocket`（或 `coder/websocket`，需二选一）；SQLite 用 `modernc.org/sqlite`（纯 Go，免 cgo）。
- **不设并发上限**是已接受的决策：M6 只展示每个会话的运行态，不拦截资源；若之后出现机器被 `npm i` 打满，再补配额。
- **v2 再谈**：上下文压缩、MCP、websearch、并行工具调用、多 provider 之外的第三家、远程部署的传输加密。
- 命令白名单的具体条目要在 M5 用真实使用数据校准一次，否则会过窄（烦）或过宽（危险）。
