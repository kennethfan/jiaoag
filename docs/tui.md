# TUI 布局与配色

这张界面只有四段，从上到下：**对话 / 模态区 / 分隔线 + 输入 / 状态栏**。顶部不再有常驻的版本或状态行；输入行紧贴状态栏，键位提示并进状态栏右侧——终端应用的惯例（vim、tmux）是最后一行永远是状态，输入就在它上面一行。

面板打开时状态栏不再重复键位——面板自己的底栏已经写了按钮与按键。

## 状态栏

左边是「在哪、在干什么」，右边是「用什么模型、花了多少」：

| 段 | 含义 | 放不下时 |
|---|---|---|
| `● 已连接` / `● 未连接` | 与服务端的 WS 状态 | 永远保留 |
| `⌂ ~/code/api` | 会话工作区（`~` 缩写，过长砍中间保留仓库名） | 倒数第二个丢 |
| `▤ 修登录超时` | 会话标题（`/sessions` 里 `t` 或 `/rename` 改）；**没起名时整段不显示**——id 是给命令行和日志用的，不占状态栏 | 较晚丢（先于工作目录丢） |
| `[运行中]` 等 | 任务状态；有审批面板时固定显示「等待审批」 | 永远保留 |
| `tsk_…` | 运行中的任务 id | 先丢 |
| `第 N 轮` | agent 轮次 | 先丢 |
| `排队 N` | 队列深度 | 较晚丢 |
| `下一条 <model>` | 用 `/model` 绑定的单次模型 | 先丢 |
| `provider/model` | 会话模型 | 只在前者都放得下时显示 |
| `12.4k tok` | 本任务累计 token | 最后才丢 |
| `enter 发送 · esc 取消 · ? 键位` | 当前可用键位（默认态才有） | 最先丢（整项放不下就省略） |

窄屏（< 80 列）先丢右侧的模型与 token，再按等级丢左侧计数；键位提示是第一个被牺牲的，按项整条省略而不是截成半句。连接状态、目录、任务状态三者永远在。

对话第一条是**入口表头**（`已进入会话：修登录超时` / `继续会话：…` / `切换到会话：…`）。它只在有标题时带标题，没标题写「（未命名，/rename 可命名）」——不摆会话 id。改名会就地改写这行（回帧与事件两条路径都改），所以第一行永远和状态栏的 `▤` 一致。

## 退出

`ctrl+c` 任何时候都能退（审批面板打开时也有效）。输入行里也可以敲 `/exit`（或 `/quit`）：它在会话检查之前处理，所以**没有会话、连接刚断**时同样能退——这两个场景恰恰是最想退出的时候。

## 样式

样式只在渲染时施加，`m.dialog` 里始终是纯文本——回放、测试、日志都不依赖转义序列。

| token | 颜色 | 用在哪 |
|---|---|---|
| accent | 青 | 提示符、选中、diff 块头、面板键位 |
| ok | 绿 | 完成、diff 增行、已连接 |
| warn | 黄 | 等待审批、排队、需要留意 |
| err | 红 | 失败、diff 删行、断线、拒绝按钮 |
| muted | 亮黑 | 元信息、耗时、路径、次要提示 |
| strong | 加粗 | 角色名、路径、当前项 |

`NO_COLOR`（任意值）或 `TERM=dumb` 关闭全部颜色，文本与布局不变；焦点用 `▸ … ◂` 包裹而不是只靠背景色，所以在无色终端里也能看出当前按钮。

## 审批按钮

三个按钮固定顺序：**批准一次 / 本会话内都批准 / 拒绝**。

- `tab` 前移、`shift+tab` 后退、`←→` 同效，`enter` 执行焦点所在的按钮。
- `y` / `a` / `n` 仍然直达，不必先移动焦点。
- 焦点落在「拒绝」时用红色描边（无色终端靠 `▸ ◂`），避免连按 tab 手滑。
- `esc` **不裁决**：只收起卡片让出屏幕，状态栏继续显示「等待审批」，再按 `esc` 展开。
- 逐块模式（`v`）下按钮换成「应用选中块 / 取消」。

## 全屏（默认）

TUI 默认占满整个窗口（alternate screen，和 vim/htop 一样）：状态栏与输入行钉在终端底行，内容超出视口后自己滚动。

滚动键：`pgup`/`pgdn` 一页、`ctrl+u`/`ctrl+d` 半页、`home` 跳到最早、`end` 回到最新。翻页期间来的新输出不会把视图拽回底部，状态栏会显示 `↕ 上翻 N 行` 和 `↓ N 新行 · end 回底`；停在底部时自动跟尾。

鼠标滚轮默认开启：滚轮事件由程序接住，滚的是对话缓冲而不是终端自身的 scrollback（否则往上滚会看到进入 TUI 之前的终端内容）。开启时会占用终端原生选中，复制文字要按住 shift。想交还终端就加 `-no-mouse`。

布局是固定的三段，高度由视口算出来，不随输出变化：

```
body   = height - 3 - modal      （内容区：只在这里滚动/裁剪）
modal  = 面板打开时的固定高度      （审批卡片、队列、模型、技能、MCP、? 帮助）
dock   = 3                        （分隔线 + 输入行 + 状态栏）
```

底部三行永远存在：没有会话时输入行显示「等待会话…」，面板打开时显示「面板打开中，esc 返回」。分隔线用 ASCII `-` 铺满，避免东亚宽度不确定的制表符把行撑破。

全屏渲染有一条硬约束：每帧的行数必须恰好等于终端高度。任何一行超出屏幕宽度都会被终端折行，整帧就多出几行，alt screen 因此产生滚动积压，底部状态栏会跟着滚走。所以内容、面板底栏、输入行都要先按显示宽度折行（或截断）再排版；输入行永远单行，超长时横向留尾。

代价：退出后终端 scrollback 里没有这段对话。需要留存用 `jiaoag events` 导出，或加 `-inline` 用内联模式——内联保留 scrollback，但状态栏会被内容推着往下走，`ctrl+f` 仍可随时切回全屏。

## 实现约定

- 颜色只用 8 色基色 + 加粗，不引入 lipgloss：宽度计算（CJK 占两列）本来就要自己写，多一个依赖只剩 API 好看。
- 所有分隔线与面板宽度按视口折行；面板固定 72 列是为了可读性，不与状态栏等宽。
- `?` 面板收纳版本、会话、工作区、附加根与完整键位，这些不进常驻行。
