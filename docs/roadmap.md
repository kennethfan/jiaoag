# 路线图与剩余工作

这份文件回答一个问题：**现在还能做什么**。已经做完的东西不再逐条列出，见 `README.md` 的进度表（v1.0–v2.26）与 `docs/adr/` 的决策记录。

## 判断标准

一个候选值不值得做，看三条：

1. **有真实痛点**，不是「架构上应该有」。
2. **不改核心不变量**——事件日志语义、状态机与审批流、权限引擎只能收紧，这三样不动。
3. **单机单用户前提下成立**，需要中心化服务或多人协作的先不做。

按这三条，供应商注册表与远程执行后端已明确关闭（收益低于维护成本），见下文「明确不做」。

## 待做

### 产品缺口

| 事项 | 状态 | 说明 |
|---|---|---|
| 移动端审批 | issue #11 | 现在裁决只能在 TUI。webhook 只负责告诉你有事，不能批。最小可用形态是服务端内置一个只读页 + 审批按钮，复用现有 WS 协议与只读令牌。 |
| 多仓库的项目级扩展 | 未开 issue | 附加根能读写、能跑命令，但 `AGENTS.md` / `.jiaoag/` 仍只读主根。多仓同时开发时，第二个仓的约定得靠提示词手写。 |
| worktree 池 | 未开 issue | 并行跑两个任务在同一仓库会互相踩工作区。worktree 池是最轻的隔离方式，但要处理「子任务结束后谁的改动算数」。 |
| 通知的分级与去重 | — | 现在所有审批都推、终态都推，长任务会把手机刷屏；也没有「同一个审批不重复推」。 |
| 令牌能力 | — | 无轮换 API（靠改配置 + `SIGHUP`）、无 per-token 限额、Windows 上没有 SIGHUP 只能重启。 |

### 工程质量

| 事项 | 说明 |
|---|---|
| `make demo` 覆盖面 | 现在只覆盖「读 → 改 → 跑测试」。加两条就能覆盖新功能：插件工具一次（`plugin__…__echo`）、附加根读写各一次（`-root lib=…`）。 |
| TUI 快照测试 | 布局靠单测断言行数与关键字符串，没有 golden 快照。60/80/120 列各存一份基准，改样式时能立刻看出回归。 |
| Windows 实机验证 | CI 只做 `GOOS=windows` 编译与 vet。Job Object 整树终止、`Path` 大小写、`!` 命令的行为都没有实机跑过。 |
| 上下文估算器跨任务累积 | 校准系数每个任务新建，首个任务偏保守。要跨任务需要落库，并解决「事件重放与系数不一致」。 |

### 运维与观测

- `jiaoag events` 没有 `--follow` 到文件轮转、没有按 action 前缀过滤（现在只能 `jq`）。
- 没有内建的指标出口（`/healthz` 只给连接数与版本，且需令牌）。
- 无审计保留策略：`events` / `audit` 表只增不删，长期运行要自己写清理。

## 明确不做

记录下来是为了避免反复讨论：

- **LLM 供应商注册表**（C2）：单用户两三个 provider，配置里的列表已经够用，注册表只增加一层间接。
- **远程执行后端**（SSH / 容器）：单机是主场景，收益低；需要时用 `exec.backend: sandbox` 已能限住写入范围。
- **并行工具调用**：与「逐个审批 + 串行审计」强耦合，收益不抵复杂度。
- **细于 hunk 的行级勾选**：hunk 是语义上能说清的最小单位，行级会让审批变成噪音。
- **执行中任务续跑**：重启只恢复 `queued`，执行中的任务一律 `canceled`。副作用无法安全重放。
- **事件日志语义、状态机、审批流程可插拔**：这是三条不变量，不开放。
- **向量检索 / 语义记忆**：`MEMORY.md` 够用，检索层引入 embedding 依赖与不确定召回。

## 怎么开始一项新工作

1. 有 issue 的先看 issue；没有就先写成 issue（模板见 `docs/agents/issue-tracker.md`），把验收标准写清楚。
2. 改动前确认它不碰三条不变量；碰了就说明理由并记 ADR。
3. 实现完跑 `make check`，需要肉眼验收的（TUI、通知、真实 provider）单独验一遍。
4. 文档同步：`README.md` 进度表加一行、`docs/design/agent-architecture.md` 对应小节更新、必要时补 ADR 与专题文档。
