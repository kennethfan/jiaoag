# ADR-0025：项目级提示、技能与 MCP

状态：已采纳（v2.11）

## 背景

前三类扩展都只认全局配置，仓库里没有载体：

- 提示词：`agent.SystemLayers` 在代码里写死成 `prompt.Builtin()`，没有配置入口；ADR-0012 设计过 `prompt_trust` 首确认，但从未实现。
- 技能：`agent.skills_dirs` 支持相对工作区的路径，但默认只扫 `~/.agents/skills`，不会自动发现仓库里的技能；同名冲突还是「先出现者赢」，机器级反而压掉项目级。
- MCP：只有全局 `mcp.servers`，一个仓库要接自己的 server 就得改全局配置。

结果是 agent 进到一个仓库后，只能靠 `MEMORY.md`（自己写的）知道「这个仓库怎么工作」；仓库作者预先写好的规则、技能、工具源都进不来。

## 决策

1. **形态走生态惯例，不自造清单**：根目录 `AGENTS.md` 是提示；`.jiaoag/` 放 jiaoag 自己的东西（`prompts/*.md`、`skills/<name>/SKILL.md`、`mcp.yaml`）；同时扫 `.agents/skills/` 以兼容跨 agent 共享目录。`MEMORY.md` 已是工作区级产物，不动。
2. **一次确认覆盖三者**：`/trust` 确认的是「当前内容摘要」，不是三个开关。摘要 = 提示的「路径 + 内容哈希」、技能的「相对目录/名字 + SKILL.md 哈希」、MCP 的「名字 + argv/env/dir 哈希」排序后 sha256。任何一处改动（包括给提示片段改名，因为改名会改变装配顺序）都会让摘要变化，需要重新确认。
3. **未确认就整体跳过，不做半开**：只加载提示不加载 MCP 这种「部分生效」会让用户以为已经审查过全部内容。跳过时只在日志与 TUI 里提示一次（`/trust` 查看并启用）。
4. **信任记录存数据目录，不落仓库**：`project_trust(workspace PRIMARY KEY, digest, trusted_at)` 迁移 0003。工作区路径统一成绝对 + `EvalSymlinks` 后的真实路径——macOS 的 `/var` 是 `/private/var` 的符号链接，不归一化会让「写入用 /var、读取用 /private/var」永远对不上。
5. **`project.mode` 三档**：`ask`（默认）/ `auto`（自己的仓库，不确认直接加载）/ `off`（完全忽略，连发现都不做）。默认 `ask` 的理由是仓库内容属于别人：clone 一个仓库等于把它的提示与命令交到 agent 面前。
6. **项目级技能覆盖机器级同名技能**：`skills.Load` 从「先出现者赢」改为「后出现者赢」，调用方按「机器级 → 项目级」排序。越近的仓库越具体，同名应由仓库覆盖。
7. **项目级 MCP 与全局合并**：`.jiaoag/mcp.yaml` 只允许 `servers:`，字段语义与全局配置一致（name/command/args/env/dir/timeout_s/trust/enabled），项目级默认 `trust: ask`。合并后的清单算一个指纹，指纹变化时重建该工作区的 MCP server，不必重启服务端。
8. **项目提示只追加**：作为独立 `prompt.Layer` 追加在技能索引之后、点名技能与记忆之前，来源写成 `project:<相对路径>`；进 `prompt.Hash`，因此进 `extensions_digest`，任务提交时冻结。

## 后果

- 仓库可以自带规则、技能与工具源，agent 进目录即按仓库约定工作；一切都在一次确认之后生效，内容变了要再确认。
- 提示总量有上限：单文件 16 KB、合计 32 KB，超出按顺序截断并标注「已截断」，不静默丢弃。
- 信任记录基于摘要，不做签名：防的是「克隆来的仓库顺手改了我的提示」，不防「本地已确认过的仓库后来被提权改写」——后者会触发重新确认，但用户可能直接点同意。
- 项目级 MCP 的 server 进程在 workspace 维度缓存；同一工作区多会话共享，会话结束不回收，进程退出时统一关闭。
- 不做项目级的供应商密钥、工具描述、压缩提示、审批话术定制：前三者属于安全边界与会话完整性的核心，后两者属于代码。

## 备选

- **`jiaoag.yaml` 单一清单**：一个文件装下提示、技能、MCP。放弃原因：提示要能分片（`prompts/*.md` 按文件名排序），技能要放正文与附带脚本，塞进一个 YAML 只会变成嵌套多行字符串。
- **逐项确认**（提示一次、技能一次、MCP 一次）：更细，但用户要连点三次，而且「只确认了提示就以为全信了」的误解更容易发生。
- **信任存仓库**（`.jiaoag/trusted`）：跟着仓库走，换机器不用再确认；但仓库内容本身就不可信，把「可信」写进不可信的地方没有意义。
- **项目级 server 一发现就启动**：会让「只是打开一个仓库」变成「执行仓库指定的命令」，与确认流程冲突。
