# ADR-0022：TUI 的本机命令（`!`）

- 状态：已采纳
- 日期：2026-11-23

## 背景

在 TUI 里跑一条 `go test ./...`、`git status`，用户有两条现成的路：切到另一个终端，或者让模型通过 `run_command` 去跑。前者打断心流；后者要花一轮模型调用、等审批，而且把「我自己的操作」混进了 agent 的上下文与审计——跑一条本地检查不该产生任务事件。

需求很窄：**输入以 `!` 开头时，把后面的部分当成本机 shell 命令执行，输出直接刷在对话区。**

约束与分歧点：

- 它是不是 agent 的工具？不是。命令由人显式输入，没有模型参与，也就没有「模型可能被 prompt 注入诱导」这个前提。审批在这里没有意义——批的是自己刚敲的命令。
- 它要不要进审计？不该。审计表记录的是 agent 的决策（谁批准了什么、命令是否被策略放行）；人肉执行的命令混进去只会稀释信号，而且那是用户自己的 shell 历史，不属于服务端事实。
- 它要不要遵守 `exec.backend: sandbox`？不该。沙箱是给 agent 选的命令加的边界；用户自己的终端不受它约束，`!` 如果被沙箱限制，会变成「同样的命令在 TUI 里跑不通、在 Terminal 里能跑通」的怪事。
- 输出要不要进模型上下文？不进。让输出进上下文需要新增一条协议入口，还要面对「这算不算一轮任务、要不要计费、截断多少」的一串问题；而真需要模型看的内容，用户贴一句话即可。

## 决策

1. **`!` 前缀的命令在客户端进程内执行，不经服务端。** 新增 `internal/localshell` 包：Unix 走 `sh -c`、Windows 走 `cmd /c`，cwd 是 TUI 的工作区，环境变量完整继承。因此管道、重定向、`&&` 都按 shell 语义生效。

2. **不审批、不审计、不受 sandbox 与命令白名单约束。** 这条路径等价于用户在自己的终端里执行——它不产生任务、不写事件、不落 `audit` 表，模型也看不到它。它与 agent 的 `run_command` 是两条独立的路，唯一共用的是「整组杀进程」的做法（各自十几行，因为 `internal/exec` 里的实现是 agent 工具专用的未导出细节）。

3. **输出流式回传，逐行渲染。** `localshell.Run.Events()` 按行给出 `Event`，最后一条 `Done=true` 带退出码、耗时与原因（超时/终止/启动失败）。TUI 用 `  │ ` 缩进渲染，与工具输出预览同一套视觉。

4. **必须持续消费事件。** 子进程的输出经管道交给 TUI，读端停下子进程就会阻塞在写操作上。因此即使显示已达上限（400 行），`Update` 仍逐条读取事件，只统计「省略 N 行」，在结束行里给出数字。

5. **收尾用整组杀进程。** 超时（默认 180 秒）与 `ctrl+x` 都杀整个进程组：`go test`、`go build` 会派生编译子进程，只杀 `sh` 会留下孤儿。Windows 上只杀直接子进程，不引入 Job Object——本地命令是临时用的，要整棵树收尾请用 agent 的 `run_command`。

6. **单行输出裁剪到 2000 rune。** 压缩过的 JS、base64 一行能到几 MB，原样塞进对话区会把终端布局冲垮。

7. **同时只允许一条本地命令，且不影响任务。** 已有命令在跑时新的 `!` 只提示；本地命令与 agent 任务并行（一个是客户端进程，一个在服务端），`esc` 仍然只作用于任务，终止本地命令用 `ctrl+x`。

8. **`!` 不需要会话。** 服务端没连上、会话还没建好时也能用——它是客户端自己的能力。

## 后果

- 用户在 TUI 里跑检查不用切终端，也不污染任务的上下文与审计。
- 输出来自客户端进程，因此**不随事件回放持久化**：断线重连触发全量重放、或 `reset` 清空视图后，之前的本地输出会消失。这是有意的取舍——它不属于会话事实。
- 本地命令继承完整环境变量（含密钥），因为它就是用户的 shell；这与 agent 的 `commandEnv` 白名单（剥离 `*_KEY`/`*_TOKEN`）是两个不同的信任前提。
- 输出上限与超时是常量，暂不可配置；需要更长的命令请直接在终端跑，或让 agent 的 `run_command` 去跑（它有输出落盘与审计）。

## 备选方案

- **做成 agent 工具（`local_shell`）**：要走一轮模型调用、写事件与审计，与「用户自己的操作」语义冲突；模型还可能被诱导执行本机命令，等于绕开审批。
- **复用 `internal/exec` 的 `Direct` 后端**：它要求 `Env` 白名单、有 `Limits` 与 capture 落盘，还要为「不审计」开后门；两边约束不同，共用只会让执行后端多出一堆条件分支。
- **输出写进模型上下文**：需要新增 `local.exec` 协议入口、定义是否计费与截断策略；收益（省一次粘贴）不抵复杂度。
