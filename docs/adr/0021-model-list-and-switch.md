# ADR-0021：运行中列出与切换模型

- 状态：已采纳
- 日期：2026-11-23

## 背景

v2.5 之前一个会话的 `provider`/`model` 在 `session.create` 时确定，之后无法更改：换个模型要新开会话，而新会话丢失上下文。同时用户不知道某家供应商当前有哪些模型可用——配置里的 `model` 只是其中一个名字，写错了要等第一次请求失败才发现。

两件事绑在一起：**先能看见候选模型，再能选中其中一个**。

约束：

- 供应商密钥只在服务端，客户端（TUI）不能直接调供应商接口。
- 会话的 `provider`/`model` 已经落库并参与任务构造，切换必须留下可回放的事实，否则重连后界面会显示过期信息。
- 供应商不一定支持 `/models`（自建网关常见），不能把「列模型」做成硬依赖。

## 决策

1. **候选列表有两个来源，配置优先。** `providers[].models` 非空时直接返回该列表（`source=config`），不发网络请求；为空时调用供应商的模型列表接口（`source=api`）。配置优先既省一次请求，也让自建网关可以手写候选。

2. **`ModelLister` 是可选能力，不进 `Provider` 接口。** 新增 `llm.ModelLister{ Models(ctx) ([]string, error) }`，适配器按需实现；不支持时返回 `ErrModelsUnsupported`。这样 `Provider` 的契约不因一个辅助能力而变宽，装饰器各自决定是否透传。

3. **请求由服务端发起，按会话当前 provider 选择。** 新增 `provider.models` 命令，服务端取会话的 `provider`（为空用默认 provider），用 `llm.New` 构造的实例调 `Models`，20 秒超时。TUI 只见结果，不见密钥。

4. **装饰器逐层透传，限流只计 RPM。** `retry`/`timeout` 转发给内层；`rate` 在转发前只等 `rpm` 桶（列模型不消耗 token）；多 key 的 `keyed` 逐 key 尝试并按原有类别冷却换 key。列模型失败因此和对话失败共享同一套重试与换 key 语义。

5. **切换落在会话上，产生 `session.updated` 事件。** 新增 `session.update` 命令与 `domain.EventSessionUpdated`，`sessions` 行更新 `provider`/`model`/`updated_at`，同事务写事件。事件可回放，TUI 重连、别的客户端订阅都能看到当前模型。

6. **切换只影响后续任务。** 任务在提交时用当时的配置构造 agent（`ExtensionsDigest` 也在此冻结），已提交/执行中的任务不受影响。不做「中断重跑」，避免同一任务半途换模型导致上下文与工具结果错配。

7. **界面是一个面板，不是自由输入。** TUI 输入 `/models` 打开候选面板（`↑/↓` 或 `j/k` 选择、`enter` 应用、`esc` 关闭），当前模型带标记；选中即发 `session.update`。不提供手打模型名，避免拼错后要等请求失败。

## 后果

- 换模型不再需要新会话，长任务的上下文可以带到另一个模型上。
- 供应商 `/models` 不可用时有明确报错，不影响对话本身；配置 `models` 可以兜底。
- `provider.models` 是明文的一次性请求，不落库、不审计：它不改变系统状态。切换本身有事件，可从 `session.updated` 追溯。
- 未实现：按任务选模型、模型能力/价格元数据、自动降级到备用模型。
- 已知取舍：`session.update` 不校验模型是否在候选列表内——候选可能来自缓存或配置，服务端只保证 `model` 非空、`provider` 存在。拼错的模型仍会在下一次请求时报供应商错误。

## 备选方案

- **`/models` 直接调用供应商接口，绕过配置**：自建网关没有 `/models` 时不可用，且每次打开面板都发请求。
- **在 `session.create` 里选模型，不做运行中切换**：实现更小，但换模型必须丢上下文，等于没解决主问题。
- **把 `Models` 塞进 `Provider` 接口**：所有适配器和测试桩都要实现一个多数场景用不到的方法，接口变宽且默认无意义。
- **切换时校验候选列表**：需要为每次切换额外发一次请求或缓存列表，收益只是提前报错；供应商侧错误已经足够清楚。
