# ADR-0055：附加根也参与项目级扩展

- 状态：已采纳（v2.56）
- 相关：ADR-0025（项目级扩展）、ADR-0036/0037（附加根）、ADR-0018（跨会话记忆）、ADR-0049（多运行时）

## 背景

v2.24/v2.25 让会话可以挂多个根（`-root lib=/path`），读写与命令都支持 `alias:path`，
但项目级扩展（`AGENTS.md`、`.jiaoag/prompts`、`.jiaoag/skills`、`.jiaoag/mcp.yaml`、
`MEMORY.md`）仍然只从主根读一份。

多仓同时开发时这很别扭：第二个仓库的约定、技能、MCP server 都得手写进提示词，
而它们本来就在那个目录里。同时也要防止「挂一个陌生仓库，它悄悄改了 agent 的行为」。

## 决策

1. **四类资产全部支持**：提示、技能、MCP、记忆。只支持一部分会让「这个仓库的规则
   生效、那个仓库的不生效」变成无法解释的行为。
2. **一次确认覆盖全部根**：`project_trust` 仍按主根路径存一条记录，但摘要覆盖
   「主根 + 各附加根的路径、别名与内容」。加挂/卸载一根、任一仓库内容变化，都要重新
   `/trust`。这比「每个根一条记录」少按几次，又不会因为确认过主根就静默接受新增根
   塞进来的文本。
3. **单根摘要保持兼容**：只有一个根有资产且是主根时，摘要与 v2.55 完全一致——
   否则升级后所有已有信任记录都会凭空失效。
4. **提示与记忆：主根在前**。提示是累加的，主根先占预算；附加根依次拿剩余额度，
   总预算仍是 32 KB（沿用 `maxPromptBytes`），不是「每根 32 KB」。记忆同理：
   主根先占 8 KB，全部根合计上限 16 KB，放不下的根在正文末尾留一句说明。
5. **技能与 MCP：主根在后（主根赢）**。`skills.Load` 是后出现者赢，MCP 合并也是
   后者覆盖前者；主根是这次工作真正的主仓库，同名时不能被某个子仓库静默替换。
   附加根之间按别名升序，靠后的别名赢靠前的。
6. **附加根的 MCP server 带来源**：`/mcp` 面板显示 `project:lib`，主根的仍是
   `project`，全局配置仍是 `config`。来源只用于展示，不影响启动参数。
7. **附加根的记忆跟随信任**：主根的 `MEMORY.md` 与以前一样无条件加载；附加根的记忆
   只在项目级扩展被加载（已确认或 `auto`）时才进入上下文——别人的仓库里的记忆同样
   是可以指挥 agent 的文本。
8. **`remember` 只写主根**：附加根只做只读注入。附加根可能是别人的仓库或只读挂载，
   写进去容易被误当成本仓库的长期事实；需要记录时由用户手动写到对应目录。

## 后果

- 提示层的来源变成 `project:lib/AGENTS.md`，提示词 hash 与 `extensions_digest` 随
  挂载的根变化；审计能回答「这段规则哪个仓库给的」。
- 系统提示里的记忆层可能分多段（`### 主根` / `### lib`），比单根时多几行标题开销。
- 摘要包含根的绝对路径：把同一个仓库挂到另一个路径下会要求重新确认。这是有意的，
  别名与路径决定了提示来源的展示与优先级。
- 挂 3 个仓库时最坏情况仍受 32 KB 提示 + 16 KB 记忆的总预算约束，不会因为根数线性
  膨胀到不可用。
- 未确认时不加载任何项目提示（含主根），沿用 ADR-0025 的整体跳过语义。

## 备选方案

- **每个根一条信任记录**：确认粒度更细，但用户要按 N 次 `/trust`，且很容易忘记某个
  根还没确认；摘要聚合后用一行记录表达同样的事实。
- **附加根只支持技能与记忆**：改动最小，但「附加仓库的 AGENTS.md 为什么不生效」会
  成为反复被问的问题。
- **附加根优先于主根**：适合「主仓库只是壳」的布局，但默认情况下会把主仓库的规则
  压掉，风险更大；需要时可以靠调整别名顺序或直接改写主根提示实现类似效果。
- **每根独立预算**：实现简单，但 N 个根就是 N 倍上下文成本，等于用挂载根数换预算。
