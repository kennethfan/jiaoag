# 不用容器隔离，权限策略是唯一安全边界

服务端在用户本机以普通进程运行，agent 的工具直接作用于真实文件系统与 shell，不引入容器或沙箱。理由是：单用户、单机、必须访问真实仓库与已安装的工具链；macOS 上的容器实际是 Linux VM，把真实仓库 bind mount 进去做 build/test 明显变慢，而维护一套镜像本身又成了新的负担。

代价是安全边界只有一层：**权限策略**（工作区路径约束、工具分级、危险命令硬拒绝）加客户端审批。任何绕过策略的执行路径都是缺陷，而不是配置问题。

## Considered Options

- **服务端容器沙箱** — 隔离更强，但 macOS I/O 性能差、镜像需要维护、真实工具链要装两遍。
- **每会话 git worktree** — 解决的是并发互踩，不解决越权，不能替代权限策略。

## Consequences

- 模型一旦构造出策略未覆盖的命令，损失是真实文件系统级别的；因此**审计记录**必须全量留存。
- 权限策略的任何放宽都需要同步更新本 ADR，否则下一个人会以为它是无意的疏漏。
- 写入必须先成为**变更提案**并经审批落盘，不允许「直接写再靠 git 兜底」。
