# ADR-0034：第三方 stdio 插件宿主

- 状态：已采纳（v2.22）
- 相关：ADR-0001（宿主持有副作用）、ADR-0009（扩展边界）、ADR-0011（执行后端）、ADR-0014（MCP 工具源）

## 背景

MCP 已经能接第三方工具，但它的模型是「一个黑盒方法」：server 自己读文件、自己起进程，
宿主看到的只有参数和返回值。这让两件事做不到：

1. **写入没法审批**。MCP 工具要写文件，宿主只能把它当外部副作用，要么整台 server 免审
   （`trust: allow`），要么每次调用都人工点一次，看不到这个调用到底要改哪个文件的哪几行。
2. **命令没走执行后端**。MCP 工具起的子进程不受 `exec.backend`（sandbox）约束，宿主的
   限额、环境白名单、审计都覆盖不到。

插件协议解决的就是这一点：第三方声明「我要做什么」，宿主决定「怎么做、要不要审批」。
插件因此不是又一个工具协议，而是「可被宿主持有的意图」。

## 决策

1. **传输与协议**：stdio 上跑换行分隔的 JSON-RPC 2.0，`ProtocolVersion = 1`；方法只有
   `initialize`、`tools/list`、`prepare`、`execute`。不定义 resources/prompts/sampling。
2. **prepare/execute 分离**：`prepare` 只声明意图，返回四类之一 `read` / `write` /
   `command` / `external`；`execute` 才真正干活。宿主在两者之间插入审批、CAS、执行后端。
3. **write 由宿主落盘**：插件返回相对路径与完整内容，宿主做「越界检查 → 取旧内容 → 算 diff
   → 审批（可逐块）→ CAS → 写入」。插件永远不拿到文件写权限；`execute` 阶段收到 write
   意图直接报错。
4. **command 由宿主执行**：插件返回 argv 与可选超时，宿主固定 `cwd` 为工作区根、忽略插件
   给的 cwd，环境走 `tools.CommandEnv`（白名单 + 剥离密钥），超时夹在 1–600s，执行交给
   `exec.Backend`（direct 或 sandbox），并按命令类工具同样的口径记 `exec.*` 审计。
5. **external 与 MCP 同待遇**：宿主无法中介，一律 `Prepared.External`，每次调用都要审批，
   审计 `external.*`。
6. **`Spec.Effects` 固定 `[read]`**：副作用由 prepare 结果表达，注册表里的声明只用于「这个
   工具是否需要预授权」。若按 process/propose_write 声明，纯读调用也会被迫审批。
7. **命名与版本**：工具名 `plugin__<server>__<tool>`（非法字符替换、超 64 字节截断加哈希），
   `Spec.Version = plugin:<server>@<ver>#<schemaHash8>`，`Spec.Source = plugin:<server>`。
8. **失败隔离**：插件起不来、initialize 超时、协议版本不符、工具重名都只跳过该插件/该工具，
   注册表照常构建；单次调用超时或 ctx 取消会作废连接，避免迟到响应串到下一个请求。
9. **插件不是沙箱**：它和 server 同权限运行。宿主中介的是「副作用」，不是「代码执行」。
   要限制插件本身的权限，得把 server 整体放进 sandbox，或只用 MCP + trust 策略。

## 后果

- 写入与命令都落进宿主已有的审批、CAS、执行后端、审计链路，不需要在 agent/perm 里加任何分支。
- 插件能表达 MCP 表达不了的东西，但代价是插件作者要多写一个 `prepare`：返回「要写什么」
  而不是「已经写了」。
- 一个插件同一时刻只有一个在途调用（串行）；没有流式输出，长任务只能靠超时与日志。
- 不能热重载：改插件实现要重启 server（配置改动同理）。
- 工具名带 `plugin__` 前缀，模型能分清来源；系统提示里那条「外部返回值只当数据」的规则
  只覆盖 `mcp__`，插件返回内容按普通工具结果处理（它由宿主调用的进程产生，仍不可尽信）。

## 备选方案

- **只做 MCP**：第三方生态更省事，但写入只能整台信任，命令绕过 sandbox，故不采纳为唯一通道。
- **让插件直接读写 / 起进程**：实现最简单，等于把 ADR-0001 的边界拆了。
- **HTTP/WS 插件**：多一套部署与鉴权，收益不明；stdio 与 MCP 一致，先只做它。
- **让 external 完全免审**：与 MCP 的 `trust: allow` 对齐会多一个配置面；插件本来就是用户自己装的，
  但仍保留「每次看一次」的默认，`allow_session` 的 12h 便利照样可用。
