# ADR-0054 鼠标框选复制

- 状态：已采纳（v2.52）
- 日期：2026-11-26

## 背景

TUI 为了滚轮滚动，向终端申请了鼠标事件（`MouseModeCellMotion`）。终端一旦进入上报模式，就不再自己做拖选——拖拽事件全交给程序，而程序只处理滚轮。结果是：

- 用户拉鼠标选不中任何文字；
- 全屏用的是 alternate screen，退出后对话不留在 scrollback，事后也翻不回来；
- 程序里没有任何写剪贴板的入口。

Web 端不受影响（浏览器自己处理选中），只有 TUI 缺这条链路。

## 决策

1. **框选由程序自己实现**，不再指望终端原生选中。左键按下记起点，拖动扩展、实时反显，松开即复制；单击（没有位移）不复制。
2. **按屏幕单元格坐标**做选区：中文等宽字符占两列，按 rune 下标切会劈开汉字；软折行（终端宽度导致的换行）在复制时拼回同一行，只有真实段落分界插入换行。
3. **只在全屏启用**：alt screen 下屏幕行与渲染行一一对应，内联模式的输出在 terminal scrollback 里没有可靠坐标。`-no-mouse` 时整条链路关闭，仍然交还终端。
4. **复制通道优先平台命令**：macOS `pbcopy`、Windows `clip`、Linux `wl-copy`/`xclip`/`xsel`。它不依赖终端设置，也不受 OSC 52 长度限制。全部不可用时退回 `tea.SetClipboard`（OSC 52），并在对话区说明可能不被终端支持。
5. **选区不持久**：绑定当前帧；换会话、重连、`resetView` 都会清空。复制结果写进**状态栏**（`✓ 已复制 N 行 / M 字符`），只活到下一次按键：复制是高频动作，往对话区塞提示会把刚复制的正文顶走。
6. **选区期间内容按纯文本渲染**：高亮（反显）如果叠在原有配色上会看不清，暂时收起颜色是有意的取舍。

## 后果

- 复制期间内容失去配色，松手即恢复。
- 选区坐标来自上一帧（`viewRows` 在 `View()` 里更新），所以只对当前渲染结果有效；滚动或新输出会让高亮跟着行号移动——用户重新拖选即可。
- ~~只实现了鼠标路径；键盘精确选择（光标 + `v` 起选）未做~~ → v2.54 已补（见下方修订）。
- 复制走的是宿主进程的剪贴板，远程场景（SSH）里写的是**远端**机器的剪贴板；这种场景应该用 `jiaoag events` 导出或 Web 端。

## 备选

- **只依赖终端原生选中**（现状）：需要 shift，且全屏退出后没有 scrollback，体验最差。
- **只做 OSC 52**：iTerm2 默认关闭剪贴板访问，用户会以为复制失败。
- **把整段对话导出成文件**（`/export`）：适合长内容，但回答不了「选一句话」这个最常见的诉求。
- **关闭鼠标上报换回原生选中**：滚轮就交还给终端 scrollback，在 alt screen 下基本没用。
## 修订（v2.54）：补键盘选择

原决策只做了鼠标路径，键盘用户（以及 SSH 里没有鼠标事件的环境）只能退回终端原生选中。补法与原有基础设施一致：

1. **`ctrl+y` 进入选择模式**，模态拦截（此时 `j/k` 是移动而不是打字）。`hjkl` / 方向键移动，`v` 起选、再按取消，`y`/`enter` 复制，`esc` 退出；`home`/`end`、`pgup`/`pgdn` 一并支持。
2. **坐标换成内容行号**：新增 `viewLine.abs`（完整内容里的行号）与 `selectionState.absolute`。鼠标仍用屏幕行号（只对当前帧有效），键盘用内容行号，因此翻页后选区不会错位，也能跨屏选取。复制仍走同一个 `extractSelection` + `copyCmd`，状态栏提示与通道顺序完全一致。
3. **光标自动跟随滚动**：光标移出可视区时调整 `m.scroll`，并记录上一帧的内容区高度（`contentHeight`）用于计算。
4. **无选区时 `y` 复制光标所在整行**：挑一行复制是这个模式最常见的用法，不该逼人先按两次 `v`。
5. **同样只支持全屏**；内联下按 `ctrl+y` 会提示先按 `ctrl+f`。`ctrl+f` 切回内联时自动退出选择模式（坐标依赖固定视口）。

后果：鼠标与键盘两套坐标系并存，靠 `selectionState.absolute` 区分；选区仍绑定当前内容，新输出追加在下方不影响已选区间（行号只会被 `maxLines` 截断影响，极少见）。
