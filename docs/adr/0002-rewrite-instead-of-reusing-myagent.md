# 从零重写，不复用 myagent 的实现

`myagent` 是同一作者已有的本地 Go agent：16k 行、测试全绿、已实现多步循环、并行工具调用、上下文压缩、真实 MCP 客户端与 HITL 确认。jiaoag 选择重写，而不是复制代码、抽公共 module 或直接改造它。

理由是它隐含的假设与 jiaoag 的客户端/服务端模型正面冲突：单进程无网络边界、审批逻辑绑在 TUI 输出上、工具执行没有工作区约束、状态存在 JSON 文件里。要复用就得同时重写 agent 循环、权限层与状态层——改造面已经覆盖它的大部分价值。而双仓共享一个内部 module，在单人项目上带来的版本同步与联调成本高于省下的代码。

## Consequences

- 上下文压缩、MCP、并行工具调用的三阶段（串行准备／并行执行／串行回填）都需要重新推导与验证。
- 因此 v1 明确不含 MCP、websearch 与上下文压缩，先确保「读代码 → 出 diff → 批准落盘 → 跑测试」这一条闭环。
- `myagent` 仍然是有价值的参照物：它的循环结构与压缩算法可作为设计输入，但不作为依赖。
