# ADR-0045：白名单可配置——默认规则落盘、只有 `default.yaml` 能放宽、风险子命令是代码底线

- 状态：已采纳（v2.42）
- 日期：2026-11-25
- 相关：ADR-0004（命令白名单）、ADR-0010（规则只能收紧）、ADR-0042（工作区写入免审）、ADR-0043（构建命令进白名单）

## 背景

v2.41 之前，命令白名单只有一份：编译进二进制的 `internal/perm/default.yaml`。`policy.d/*.yaml` 里的规则在加载时被硬置 `Tighten = true`，只能把调用推回审批，永远放不出「允许」。

这带来两个问题：

1. 想放行一个自用工具（例如 `python3 -m pytest`、`terraform plan`）只能改代码发版，或者干脆不用 agent。
2. 白名单是**隐藏**的：用户看得见命令被拒，却看不见完整的允许集合，也看不出「为什么 `-o` 被拒」。

同时，ADR-0010 的「外部规则只能收紧」必须保留：`policy.d` 与签名 feed 共用目录，一旦整个目录可放宽，往目录里丢一个文件（或让 feed 签发一条 allow）就能拿到全部权限。

## 决策

1. **默认规则落盘，不做隐藏内置**。二进制里的 `default.yaml` 只作为**模板**：首次启动（或目录为空时）写到 `policy.d/default.yaml`（0644），之后运行时只读磁盘文件。写失败直接启动失败并提示手动创建——不能「用户以为在编辑一份文件，实际跑的是另一份隐藏规则」。
2. **只有 `policy.d/default.yaml` 可以放宽**。同目录其他 `*.yaml` 与签名 `feed.yaml` 仍强制 `Tighten = true`。放宽权限由**文件身份**表达，代码里可验证；往共享目录塞文件仍然只能收紧。
3. **不覆盖用户文件**。文件已存在就只读，即使内容被改得面目全非；版本落后于内置模板时只打一条 warn，并说明新版安全修复不会自动合入。静默覆盖会把用户改过的条目抹掉，比错过更新更糟。
4. **复用完整 `Rule` schema**：`programs` / `subcommands` / `allow_flags` / `deny_flags` / `path_args` / `reason`。用户可以写「`python3` 只允许 `-m pytest`」这类规则，而不是只能按程序名全放行。
5. **`risk_subcommands` 是代码级底线**。`npm publish`、`pnpm dlx`、`mvn deploy`、`gradle publish`、`make install` 等子命令即使从 `default.yaml` 里全部删掉，仍然落到审批（`builtinRiskySubcommands`）。规则文件只能**增加**风险子命令，不能减少。理由：这类动作把东西送出本机、操作凭据，sandbox 与 git 都救不回来。
6. **flag 限制留给文件**。`-o`、`-toolexec`、`make -f`、`mvn -Dmaven.repo.local` 写在 `default.yaml` 里，用户显式删掉就真的放开。与第 5 条的区别是可逆性：flag 只影响这一次命令做什么，发布类动作不可回滚。
7. **仅启动时加载**。改完重启生效；`policy_hash` 覆盖全部规则内容与版本，启动日志打印 `policy`、`policy_hash`、规则条数、目录与 warning。热重载会让「正在跑的任务用的哪套规则」难以回答，收益也小。
8. **项目级不参与**。`.jiaoag/` 与仓库内容不能放宽权限（只能通过收紧通道），放宽的唯一入口是宿主配置目录。

## 后果

- 新装即用：首次启动生成一份带注释的默认白名单，`go build` / `npm run` 等开箱可用。
- 用户对自己编辑的规则负责：删掉 `deny_flags` 里的 `-o` 就是放开了 `-o`，审计里的 `policy_hash` 会变。
- `npm publish` 类动作无法通过配置放行，想改只能改代码——这是刻意的摩擦。
- 升级不会自动获得新默认条目（例如将来新增的程序白名单）；启动日志会提示版本不同。
- 已有安装首次升级后目录里会多出 `default.yaml`；原先只有收紧规则的目录行为不变。

## 备选方案

- **纯手写、缺失即全部审批**：更「无隐藏」，但首次安装后 agent 几乎不能执行命令，体验断崖。
- **把 allow 规则写进 `config.yaml`**：规则 schema 会与 `Rule` 结构漂移，且配置文件已经很长。
- **整个 `policy.d` 都可放宽**：破坏「往目录丢文件只能收紧」的不变量；签名 feed 与本地文件混在同一信任级别。
- **把风险子命令也交给文件**：一次复制粘贴就可能永久放开 `publish`，与「发布不可回滚」的判断冲突。
- **SIGHUP 热重载规则**：留给以后，和 `policy.d` 一起做。
