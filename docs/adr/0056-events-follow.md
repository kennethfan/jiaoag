# ADR-0056：`jiaoag events --follow` 常驻采集

## 背景

`jiaoag events` 原本已经能「跟随」：不给 `--until-now` 就一直读到 Ctrl+C。但它只适合人在终端里看，不适合当成常驻采集进程：

- 输出只有 stdout，落盘要靠 shell 重定向；而 shell 重定向的 fd 在日志轮转后就指向被改名的旧文件，采集悄悄断流。
- WS 断开（服务端重启、网络抖动）就直接报错退出，没有重连。
- 没有过滤，一个会话的 `assistant.start` / `round.started` 这类低价值事件占满管道。

## 决策

1. **新增 `-follow`，语义是「常驻采集」**：断线按 500ms → 1s → 2s → 5s 退避重连，带上已导出的 `seq` 与审计 `id` 续传。与 `--until-now` 互斥（一个要一直跟，一个要导到启动时刻就停）。
2. **`-output` 写文件，`-follow` 时追加、否则覆盖**。快照导出覆盖旧文件符合直觉；跟随采集必须追加，否则每次重启都抹掉历史。
3. **轮转检测在写入侧做**：每写一行前 `os.Stat` 路径并与持有的 `FileInfo` 比 `os.SameFile`，不同就 `O_CREATE|O_APPEND` 重开。不做定时器——没有写入就没有日志可丢，按写入检查足够且零额外 goroutine。
4. **`-action` / `-type` 前缀过滤，可重复，OR 语义**。`-action exec` 同时命中 `exec.allow` 与 `exec.approved`（审计按 `动作.子动作` 命名）；`-type approval` 命中 `approval.requested/resolved`。前缀比精确匹配更符合「按类别筛」的实际需求，代价是要精确时得写全名。
5. **过滤只影响输出，不影响游标**。被过滤掉的记录照样推进 `seq` / `id`，否则重连后会把它们再拉一遍。
6. **直连模式同样支持**，只是没有重连：库就在本地，读不到就报错退出，比静默空转更好。

## 后果

- 采集进程可以交给 supervisor 长期跑，轮转与重连都不用外部脚本兜。
- 过滤是「导出前」而不是「导出后」，管道里只有关心的行；代价是同一份 JSONL 里看不出被过滤掉了什么。
- 与 `--until-now` 互斥意味着不能「导完历史后转跟随」一步完成；需要的话跑两次（先 `--until-now` 导历史，再 `--follow -from <head>` 跟随）。
- 轮转检测依赖路径本身（而不是 fd）；如果外部工具把日志写进同一路径但内容不换 inode（少见），不会重开——这种情况通常也不需要重开。

## 备选

- **只补 SIGHUP 重开文件**：能处理轮转，但处理不了断线重连，且要额外约定信号语义。
- **自己负责轮转（按大小/时间切分）**：等于把 logrotate 的职责搬进程序，配置面变大；外部工具已经够用。
- **用 `tail -F` 套一层**：`stdout` 时可行，但 WS 断线仍然退出，且多一个进程要管。
- **精确匹配代替前缀**：`-action exec.allow` 更严谨，但常用场景是「所有执行类」，前缀更顺手；精确匹配随时可以当成前缀的特例用。
