# 36. 只读附加根：一个会话看多个仓

- 状态：已采纳（v2.24）
- 日期：2026-11-24
- 相关：ADR-0004（工作区边界）、ADR-0015（sandbox 可写范围）、issue #12 / #13

## 背景

实际开发经常同时看两个仓：主仓在改，依赖库在另一个目录。现在的模型只认一个工作区根，
要么把库拷进来（脏且误导），要么切会话（事件、审批、审计全断）。

完全等价的多根（任何根都能写、能跑命令、能注入项目提示）改动面很散：路径校验、CAS、
审批路径、`path_args`、sandbox 可写范围、项目级扩展全要按根展开。所以先做一层**只读附加根**：
能看能用，但没有第二个写入口。

## 决策

1. **附加根只读，主根唯一可写**。这条不是提示词约束，而是工具层边界：写入类工具直接报错，
   命令的 cwd 永远是主根。
2. **会话属性**：`sessions.roots` 存 JSON `[{alias,path}]`（迁移 0006）。附加根属于会话，
   不是全局配置——同一个仓在两个会话里可以挂不同的别名组合。
3. **访问形式 `alias:path`**。别名只允许小写字母开头、字母数字与 `_-`、最多 32 字符。
   前缀形如别名但没有挂载时报 `workspace: 未知的根别名`，而不是把它当成主根下带冒号的文件名：
   拼错别名应该立刻被发现。
4. **读工具穿透**：`read_file` / `grep` / `glob` 接受 `alias:path`（glob 接受 `alias:**/*.go`）。
   `grep` 结果的每行、`glob` 的每个文件都带 `alias:` 前缀，模型看到的结果能自证来源。
5. **写工具显式拒绝**：`write_file` / `edit_file` 遇到已知别名前缀时报
   `workspace: 附加根只读`，而不是把带冒号的名字写进主根。
6. **不参与三处机制**：`path_args`（命令 cwd 仍是主根）、sandbox 可写范围（只含主根与缓存）、
   项目级扩展（AGENTS.md / `.jiaoag` 仍只从主根读一份）。
7. **创建即校验**：别名非法、重复、与主根同目录、目录不存在，都在 `session.create` 时失败，
   而不是等到第一次 read 才报错。
8. **不做可写与命令**：留给 A2（issue #13），那需要 `tools.Change.Root`、审批路径带 alias、
   sandbox 多可写根与项目提示按根注入。

## 后果

- 多仓只读浏览不需要复制目录，也不需要第二个会话；事件流与审计仍然只有一条。
- 模型必须显式写 `lib:xxx` 才能读到附加根；不带前缀时的行为与之前完全一致（现有测试不改）。
- 附加根里的内容不进系统提示、不进 `extensions_digest`，换根不影响任务指纹。
- 只读是工具层保证，不是沙箱保证：附加根里的文件仍可被 `!命令`（客户端本地执行）读改，
  那是用户的 shell，不属于 agent 边界。

## 备选

- **完全等价多根**：能力最全，改动最散，且「哪个根是可写的」会变成审批界面的智力负担。
- **只允许同一父目录下的兄弟目录**：省掉别名，但把仓库布局强加给用户。
- **改用 git worktree / monorepo**：零成本，但解决不了「依赖库是另一个 git 仓库」的常态。

## 修订（v2.25）：附加根改为可写

ADR-0037 把附加根开放为可写，并允许 `run_command` 用 `root` 指定执行目录；本文中
「写入与命令只限主根」的约束已被取代，其余决策（别名形态、路径校验、项目扩展只读主根、
不计入 `extensions_digest`）保持不变。
